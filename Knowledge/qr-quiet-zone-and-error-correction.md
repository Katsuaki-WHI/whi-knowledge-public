# QRの静穏帯と誤り訂正（読み取れないときに最初に見るところ）

QRが「読めるときと読めないときがある」場合、コードの中身より先に**周りの白い余白（静穏帯）**と
**誤り訂正レベル**を疑う。どちらも既定のままだと規格を下回りやすい。

## 1. `react-qr-code` は余白を一切付けない

```js
// node_modules/react-qr-code/lib/index.js
level = _ref$level === void 0 ? "L" : _ref$level,   // 既定は L（7%まで復元）
viewBoxSize: moduleCount                             // = 静穏帯ゼロ
```

- **`viewBoxSize` がモジュール数と同じ**＝SVGの端まで黒が来る。**呼び出し側の padding が、そのまま静穏帯になる。**
- **`level` を渡さないと `L`**（最弱）。汚れ・かすれ・画面の反射に弱い。
- QR規格（JIS X 0510 / ISO 18004）は**静穏帯4モジュール以上**を要求する。

## 2. 実際に足りていなかった（実測）

カードの `padding: 14px` に対し、1モジュールが 4.55px なら静穏帯は **3.08モジュール**＝不足。
「余白を取っているつもり」でも、モジュールの大きさ次第で簡単に下回る。

| 経路 | 修正前（モジュール換算） |
|---|---|
| 画面 | 上3.27 下1.64 左3.27 右3.04 ❌ |
| 印刷 | 上1.16 下3.48 左1.16 右1.06 ❌ |
| コピー画像（canvasで自前描画） | 4.00 ✅ |

★**「保存する画像だけ正しく、画面と印刷が不足」**という形になりやすい。
自前で canvas に描く経路では静穏帯を意識するのに、ライブラリ任せの経路では忘れるため。

## 3. 直し方

1. **設定を1ファイルに集約**（誤り訂正レベル・静穏帯のモジュール数・表示サイズ）。経路ごとに直書きしない。
2. **QRを出すところは必ず共通部品を通す**。部品の中で「白の padding」として静穏帯を確保する。
3. **静穏帯の px は決め打ちにしない**＝モジュール数は文字列の長さで変わる。
   `Math.ceil(表示サイズ / モジュール数 * 4)` で算出し、**端数は切り上げ**（丸めで4を下回らせない）。
4. **枠線・影・角丸は静穏帯の外側に出す**。余白に食い込むと静穏帯として働かない。
5. **誤り訂正を上げるとモジュールが細る**（例 29×29 → 33×33）。表示サイズも一緒に上げて、
   1モジュールの大きさを維持する。
6. **地は固定の白**にする（テーマの色トークンを使わない）。端末がダークモードでも反転させない。

## 4. 検証（ここまでやらないと直ったと言えない）

- **描画された画素で実測**する。CSSの指定値ではなく、実際に何px空いているかを測る。
- **画面・印刷・コピー画像の3経路すべて**。1つ直すと他が置き去りになる。
- **モジュール数で誤り訂正を確認**できる（同じ文字列で L=29×29 → M=33×33）。
- **実際にデコードする**。macOS なら Vision（iPhoneのカメラと同じ検出エンジン）で確認できる。
- **読み取り限界を比べる**と改善幅が分かる（画面QRを縮小して読める最小サイズ／印刷PDFの解像度）。

## 5. 併せて：QRが読めない人への逃げ道

QRは必ず失敗する人が出る（カメラが古い・光が強い・紙が折れた）。
**招待コードを手で入力できる入口があるなら、その存在をQRの近くに1行で案内する。**
機能があっても、案内が無ければ無いのと同じ。
