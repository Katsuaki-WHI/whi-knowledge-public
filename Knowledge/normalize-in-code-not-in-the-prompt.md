# 意味が同じで形だけ違うものは、AIに守らせ続けるのでなく、コードでそろえる

**「この形で書いて」と頼んで守られないとき、頼み方を強めるより、あとから整えるほうが安くて確実。**

## 実際に起きたこと

材料に「**"We want to …" で始める**」と書いたのに、AI は **"This team wants …"** と書いた。
2本続けて同じ形だった。**意味は同じで、形だけ違う。**

- 言い方を強める → 1回の生成ぶんの費用がかかり、次も守られるとは限らない
- **コードで置換する** → 1回書けば、以後は必ずそろう。費用は0

さらに、**日本語でもまったく同じ崩れ方をした**（「**このチームは、**…」が3つとも）。
「日本語は通っている」と思っていたが、前の回がたまたま通っていただけだった。
★**片方の言語で起きた形の崩れは、もう片方でも起きると考える。**

## 分かれ目＝「意味が変わるか」

| | 扱い |
|---|---|
| **意味が同じで形だけ違う**（主語の言い換え・引用符・語尾・記号） | ★**コードで正規化する** |
| **意味が変わる**（事実・向き・数字・誰のことか） | **ゲートで止めて、作り直す**（勝手に書き換えない） |

正規化は「書き換え」なので、**意味に触れた瞬間に危険**になる。
文頭の主語のように、**落としても足しても意味が変わらないところ**に限る。

## どこでやるか

★**保存の前・判定の前**。整えたものを判定し、整えたものを保存する。
（後ろ＝表示のときに整えると、**保存されたものと画面が違う**ことになる。）

## 気をつけること

1. **対象の欄を鍵で限定する**（本文の言い回しには触らない）。
2. **元から正しいものは変えない**（置換前後が同じなら何もしない）。
3. **何を変えたかを残す**（ログに欄の名前を出す。黙って書き換えない）。
4. **固定ケースで3つ見る**＝置換される／元から正しい／関係ない欄は触らない。
5. ★**言語ごとに規則を分ける**（日本語と英語で、同じ意味の言い換えの形は違う）。
