# 文字の読みやすさ（コントラスト比）は描画画素で測る。ただし「どれが文字か」を2回まちがえる

★**計算値（CSS の色）だけでは測れない**＝透明度・グラデーション・重なった塗りがあると、
実際に目に入る色は CSS に書いてある色ではない。→ **その要素を撮って、画素から測る。**

やり方＝要素の矩形を撮る → 画素の色を数える →
**いちばん多い色＝地**／**地といちばん明るさが離れた色＝文字** として比を出す。

## ★この決め方は、2つの形でまちがえる

### ⑴ 枠・隣の塗りを「文字」と取り違える（＝ありえない低い比が出る）

実例＝金色のピル（金の地に濃い文字）。**枠ごと**撮ると **1.99**、**内側だけ**撮ると **8.18**。
原因は**外周のクリームの枠**で、クリームは地の金より「明るさが離れている」ので文字より先に選ばれる。

| 内側に入れる量 | 比 | 文字として選ばれた色 |
|---|---|---|
| 0px（枠込み） | 1.99 | クリームの枠 |
| 2px | 1.97 | 同上 |
| **4px** | **8.18** | **CSS の色と一致** |

→ **内側に少し入れて撮る**（枠・影・角丸を外す）。

### ⑵ ★地と文字の役が入れ替わる（＝値は正しいが、名前が逆になる）

**狭い範囲いっぱいに文字が詰まっている**と、**文字の色のほうが「いちばん多い色」**になる。
すると「いちばん多い色＝地」という決め方が裏返り、**地と文字が逆に出る**。
★**比の値は同じ**（コントラスト比は左右対称）なので**合否は変わらない**が、
「文字の色が CSS と違う＝偽の読み」という見分け方をしていると、**正しい読みを偽物と判定する**。

実例＝10px の小見出し。1280px では `fg=138,90,0`（CSS と一致）、
375px では `fg=255,251,230`（クリーム＝地のほう）。**比はどちらも 5.64 と 5.70 でほぼ同じ。**

## ★★見分け方（これが結論）

**読みが本物なのは、測って出た2色の「どちらか一方」が CSS の色と一致しているとき。**
（「文字として選ばれた色が CSS と一致」では狭すぎて、⑵ を偽物にしてしまう。）

```js
const dev = (c) => Math.max(...cssRgb.map((v, i) => Math.abs(v - c[i])));
const real = Math.min(dev(fg), dev(bg)) <= 12;   // ★どちらか一方で見る
```

## ★あわせて守ること

- **日英 × 広い幅／狭い幅** の全通りで測る（**同じ部品でも位置によって地が違う**）。
- **最後はスクリーンショットを自分の目で見る**（数字だけで「読める」を決めない）。
- **開くと書く画面を避ける**（結晶化・再計算の保険コード）＝**開く前後でDBの件数と日時が同じ**ことを示す。
- ★**低い比が出たら、まず「本当に文字を測ったか」を疑う。**
  実例では「4.5:1 未満 53件」のうち **24件が偽の読み**で、直す必要が無かった。
