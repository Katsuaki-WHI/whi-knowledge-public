# 使い捨ての PostgreSQL で SQL を確かめるときの落とし穴4つ

本番に当てる SQL は、**使い捨ての PostgreSQL に「権限のかたち」だけ再現して
当てる→照合→戻す→当て直す**を先に通す。そのときに自分で踏んだ穴。
どれも**検査が「○」を出すのに中身は確かめられていない**という形で出るので、たちが悪い。

## 1. `psql -c "set role X; …"` は1行目に `SET` を出す

値を取ったつもりが `"SET\n2"` という文字列になる。`=== "2"` が通らない。
→ **`-q` を付ける**（`SET` も `INSERT 0 1` も出なくなり、値だけが返る）。
あるいは「最後の行」を取る——ただし `insert … returning` では最後の行が
`INSERT 0 1` になるので、`-q` のほうが確実。

## 2. stderr を捨てると「権限で止まった」と「別の失敗」が区別できない

`stdio: ["ignore","pipe","ignore"]` で stderr を捨てると、失敗の中身が見えない。
このとき **「エラーが出たら合格」** という書き方をしていると、
**`role "anon" does not exist`（＝テスト環境の作りそこね）でも合格になる**。
→ **stderr を混ぜて受け、合格条件を `permission denied` に限定する。**
★一般則＝**「失敗したこと」を合格条件にするなら、失敗の種類まで見る。**

## 3. 複数行の SQL を `-c` に埋めると、改行が文字の `\n` になる

シェルへ渡すときに `JSON.stringify` などで包むと改行がエスケープされ、
psql は `\n` を**テキストとして**受け取って `syntax error at end of input` になる。
→ **ファイルに書いて `-f` で流す**（`docker cp` して `psql -f`）。

## 4. 起動待ちを「accepting connections」で見ていない

`pg_isready` はまだ立っていないとき `no response` / `rejecting connections` を返す。
「error という字が無ければ OK」のような緩い判定だと**立つ前に先へ進み**、
`create role` が黙って失敗し、**そのあとの検査が全部おかしくなる**。
→ **`accepting connections` を含むことを条件にする**／
**立たなかったら、そこで不合格にする**（立たないまま測らない）。

## おまけ：再現する「かたち」は本番と同じにする

本番の主キーが uuid なのにテストで `serial` にすると、
**シーケンスの権限**という本番に存在しない論点が混ざり、
「service_role が書けない」という**偽の不合格**が出る。
→ **列の型・既定値まで本番に合わせる**（本番を読むだけで確かめられる）。

## 通すべき6つ

⑴当てる前は `ok_` が **false**（★検査が本当に見分けているか）
⑵当てたら `ok_` が全部 true
⑶閉じたい相手から**読めない・書けない・TRUNCATE できない**
⑷通したい相手は**従来どおり読み書きできる**
⑸**冪等**（2回当てても同じ）
⑹**戻すと元に戻る・行は1行も消えない**／戻したあとでも**当て直せる**
