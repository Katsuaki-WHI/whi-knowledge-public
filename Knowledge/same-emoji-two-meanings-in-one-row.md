# 同じ絵文字を、同じ行で別の意味に使わない

一覧は**上から目を走らせる**場所なので、同じ記号が並ぶと読み手はそれを「同じもの」と受け取る。
**1つの行の中で同じ絵文字が2つの意味を持っていると、一覧としての機能そのものが落ちる。**

## 起きたこと

メンバー一覧の1行に、同じ絵文字が2つ並んだ。

```
名前  👑        [👑 役職]
      ↑上位商品   ↑役職
```

- 片方は**上位商品を買った印**（その商品のページで使っている記号）
- もう片方は**役職の印**（チップの中で文字と一緒に使っていた記号）

**両方とも、それぞれの画面では正しい記号**だった。ぶつかったのは、
**別々に決まった2つの正しさが、1つの行で初めて隣り合ったから**。

★**これは例外ではなく普通に起きる組み合わせだった。**
その上位商品を買うのはたいていその役職の人なので、**ほぼ毎回ぶつかる**。
「珍しいケース」と見積もると対応を後回しにしてしまう。
**ぶつかる条件が「よくある組み合わせ」かどうかを先に確かめる。**

## 気づきにくい理由

- **どちらの画面も単体では正しい。** それぞれを見ているかぎり違和感がない。
- **読み上げ（aria-label）や補足の吹き出しでは意味が取れてしまう**ので、
  機械的な検証はすべて通る。**目で一覧を眺めて初めて分かる。**
- 実装した本人は意味を知っているので、**並んでいても読めてしまう**。

## どう直すか

1. **記号の意味を全部洗い出す（grep）。** 同じ絵文字が製品内でいくつの意味を持っているかを数える。
   実例では3つあった（キャラクター本人／上位商品／役職）。
   **2つ以上あること自体は悪くない。問題は「同じ行に同時に出るか」。**
2. **残すのは、外の画面と揃っている側。**
   その商品のページで使っている記号は動かさない（動かすと、そこで新しい不一致ができる）。
   **同じ行の中で意味が決まらない側**を、文字など別の表し方に変える。
3. **同じ意味の他の場所まで機械的に変えない。**
   実例では、同じ記号を役職に使っている箇所がもう1つあったが、
   **その画面には商品の印が無く、ぶつからない**ので変えていない。
   「揃える」を目的にすると、ぶつかっていない場所まで触って差分が広がる。

## 予防

- **一覧の1行に新しい記号を足すときは、その行に既にある記号を全部数えてから決める。**
- **記号は「どの画面で何を指すか」を1箇所に書いておく**（増えたときに衝突を見つけやすい）。
- **検証は必ず一覧を目で見る。** 要素の有無・読み上げ文言・件数だけでは、この種の混同は検出できない。
