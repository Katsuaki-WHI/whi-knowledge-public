# CLAUDE.md には上限がある（15万字）。超えると後半が読まれない

## 事実

**CLAUDE.md は約15万字が上限**。これを超えると、超えた分（＝**後半**）が
セッション開始時に読み込まれない。**エラーは出ない**ので、気づかないまま
「書いてあるのに守られない」状態になる。

★**いちばん危ないのは、後半に置かれがちなもの**が読まれなくなること：
- **未処理タスク欄**（先送り防止の正典）
- **絶対ルール**
- **最近の本番反映記録**

つまり**「読まれないと困るもの」ほど、放っておくと落ちる位置に来る**。

## なぜ起きるか

CLAUDE.md は「実装記録」として書き足していく運用になりやすく、
**本番反映のたびに数千字ずつ増える**。1日に複数回反映する日が続くと、
1〜2週間で数万字増える。なかまサーベイでは **2026-09-04 時点で29万字**に達していた
（上限のほぼ2倍＝**後半の半分近くが読まれていなかった**）。

## 運用ルール

1. **本番反映記録は「直近2週間」だけ CLAUDE.md に置く。**
   それより古いものは `docs/claude-md-archive/YYYY-MM.md` へ**移動**する（削除ではない）。
2. **月末に棚卸しする。** 2週間より古い記録を archive へ移す。
3. **15万字を超えない。** 目標は**12万字以下**（余裕を持たせる）。
4. **セッション開始時に文字数の警告が出たら、最優先で分割する。**
   他のタスクより先に行う（読まれていない状態で作業を進めると、
   ルールを知らないまま実装することになる）。
5. CLAUDE.md 冒頭に「詳細な履歴は `docs/claude-md-archive/` を参照」と1行置く。

## CLAUDE.md に残すもの／移すもの

| 残す（毎回読む価値がある） | 移す（必要なときだけ見る） |
|---|---|
| プロジェクト概要・技術スタック | 過去の本番反映記録（2週間より前） |
| 絶対ルール | 完了済みスプリントの詳細（Step 3-x 等） |
| 現行仕様の要点＋参照先 | 古い検証記録・見送りの記録 |
| **未処理タスク欄** | 過去の障害記録の詳細（教訓は mistakes.md へ） |
| 直近2週間の本番反映記録 | 設計の変遷（結論は Decisions へ） |
| 重要な設計判断の**見出しと Decisions への参照** | その設計判断の全文 |

★**判断の本体は Decisions/ に置き、CLAUDE.md には見出しと参照だけ**を書く。
CLAUDE.md を「索引」として使えば、太らない。

## 文字数の測り方

```bash
python3 -c "import io;print(len(io.open('CLAUDE.md',encoding='utf-8').read()))"
```

分割したら、**移動前後の合計文字数が一致すること**を確認する（内容を落としていない証拠）。
