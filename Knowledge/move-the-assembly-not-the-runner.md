# 走らせる側を触らずに、組み立てだけを変える（新しい版をデプロイなしで流す）

★**AI 生成のような「重い仕事」を別の実行体（サーバーレス関数など）に投げている作りで、
新しい版（新しいプロンプト・新しい章立て）を足すときの型。**

## 何が決め手か＝ランナーが「中身を見ない」かどうか

走らせる側（ランナー）が、ジョブ行から**次の4つを受け取るだけ**なら、
★**新しい版は「組み立て」を変えるだけで流せる**（★ランナーのデプロイが要らない）。

| ランナーが読むもの | 誰が作るか |
|---|---|
| system prompt | ★呼ぶ側（アプリ） |
| 材料（user message） | ★呼ぶ側 |
| 道具の定義（出力の形） | ★呼ぶ側 |
| 保存前の判定に渡す材料 | ★呼ぶ側 |

★**逆に、判定そのもの（ゲート・正規化）がランナー側の束（バンドル）にあるなら、
そこを変えるとデプロイが要る。** → **だから、そこは触らない。**

## そうすると、新しい版の「約束」を2つに分けることになる

1. ★**既存の判定で効くもの**＝そのまま使う
2. ★**効かないもの**＝**生成のあとに、呼ぶ側で別に見る**

★★**1 を「効く／効かない」で思い込まず、実測して検査に固定する。**
実例＝新しい版の7欄を既存の判定に通したら
**「欄の形」の違反は0**（渡す定義が新しい版のものなので形は合う）／
**総字数は効く**／**「材料に無い数字」が重い違反として効く**
（＝新しい版の「本文に数字を書かない」という約束が、既存の判定でそのまま守られた）。
→ ★**この表を検査にすると、どちらかが変わった日に落ちる**（＝「壊れない」が約束になる）。

## ★渡さないことで、噛み合わない判定を外せる

判定の材料は**任意**であることが多い（渡さなければ何も見ない）。
★だから**新しい版と噛み合わない判定は、材料を渡さないことで外す**。
実例＝既存の「本文に本人の名前が出たら重い違反」は、
**新しい版が「同意があれば名前を出す」設計**だと噛み合わない → **名前を渡さない**。
★★**外した理由をコードに書く**（書かないと、次の人が「渡し忘れ」として足してしまう）。

## ★できないことは、構造で言い換える

★**「判定に落ちたら保存しない」はランナーがやるので、呼ぶ側からは止められない。**
→ ★**「保存しない」ではなく「届かない」で目的を満たす**。
実例＝新しい版は**開発中の棚**に積むだけで、お客さまの画面はその棚を読まない
（別のガードで閉じている）＝**「悪いものをお客さまに届けない」は構造として満たされている**。
★**そのうえで、生成のあとの検査は「作った人が品質を見るため」のものと位置づける**
（★落ちたら画面に赤く出す）。
★★**できないことを「できた」と書かない**＝記録に「保存は止められない／ただし届かない」と並べて書く。

## 確かめ方（★この2つで「触っていない」を言い切れる）

1. **バンドルとソースの一致検査**（機械が作った束が、もとと同じか）
2. ★**`git diff --stat <ランナーのフォルダ>` が差分0**（★検査の項目にする＝毎回数える）

## 気をつけること

- ★**束（保存の単位）を分ける**＝新しい版は**別の版番号**で保存する
  （既存の棚に触らない／既存の表示は1行も変わらない）。
  ★版番号の列に CHECK が無ければ **SQL も要らない**（先に確かめる）。
- ★**組み立ては1か所**＝「材料を見る画面」と「生成」が**同じ関数**を通す
  （写しを作ると、画面で見た材料と AI に渡る材料が別物になる）。
- ★**二重走行を止める索引の鍵に「束」が入っているか確かめる**。
  入っていないと、**同じ人・同じ言語なら版が違っても「同じ1本」**として扱われ、
  **画面は「作りました」と言うのに新しい版の本文は永久にできない**。
  → 索引を直すまでは**「走っている1本が別の束なら止める」**（押し直せば作れる）。
- ★**長さの前提を数える**＝骨（材料の文）の合計が、判定の下限より短いことがある。
  実例＝骨 1,108字／伝える長さ 2,000字／判定の下限 1,500字
  ＝**AI は「文にする」ぶんで埋める**見込みだが、★**実際どうなるかは1本通して初めて分かる**。
