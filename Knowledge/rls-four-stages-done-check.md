# RLS を掛け終えたあと、何をもって「閉じた」と言うか

4段方式（①コードを service_role へ → ②RLS 有効化 → ③anon を REVOKE → ④照合）の
**④で測るもの**。「SQL が通った」「`ok_` が true」だけでは足りない。

## 1. ★外から実際に叩く（カタログを見るだけで終わらせない）

照合SQL（`ok_` の列）は**DBの内側から**見た姿。
**公開 anon キーで、外から本当に叩く**のが④の本体。

- 閉じた表＝**`42501 permission denied`**
- **読みだけでなく INSERT / UPDATE / DELETE も叩く**
  （★本番を汚さない形で＝存在しない名前を条件にした UPDATE/DELETE、
  　INSERT は「絶対に残ってはいけない名前」で。通ってしまったら即わかる）
- ★**閉じる前の数字と並べて書く**（「156行 読めた → 42501」）。
  **「読めない」だけだと、元から空だったのか閉じたのかが読む人に伝わらない。**

## 2. ★全部の表を叩く（閉じた表だけ見ない）

閉じた表だけ確かめると「**ほかに開いている口**」を見落とす。
PostgREST の `/rest/v1/` のルートは**その鍵で見える表の一覧**を返すので、
**service_role で一覧を取り、anon で全件叩く**と、外から見える範囲が丸ごと出る。

★このとき **「200 だが 0 行」** が出たら、**空なのか RLS が止めているのか**を分ける
（service_role で実際の行数を数えて並べる）。
実行数があるのに anon で 0 行なら「**RLS が止めている＝中身は漏れていない。
ただし GRANT は残っている＝守りが1枚薄い**」。これは**別の宿題として起票する**。

## 3. ★「同じ中身が出ている」を数字で示す

画面の確認を「200 が返った」で終えない。
**閉じる前に測った本文の長さを、閉じたあとにもう一度測って並べる。**
長さが1字も変わっていなければ「**落ちていないだけでなく、同じものが出ている**」と言える。

## 4. ★読むだけの確認でも「開くと書く画面」を避ける

「開いたときに固める」保険コード（結晶化・再計算・自動修復）があると、
**閲覧しただけで本番に書き込みが起きる**。
→ **開く直前に、その条件に当たらないデータを本番から選ぶ**。
→ **前後で行数＋「書かれる列が埋まっている行の数」を数えて一致を示す。**

★**AI と外部APIを呼んでいないことも、件数で示せる**
（AI の台帳・ジョブの表が動いていない／取り込み先の表が動いていない）。
「呼んでいません」と書くより強い。

## 5. ★★④で、前の段の「写した事実」が1つ落ちた

段階0 で「Edge Function は `survey_sessions` を読む」と書いていたが、
**実際は1つも読んでいなかった**（材料は生成APIが組み立ててジョブ行に入れ、Edge はそれを読む）。
結論（Edge は service_role なので RLS の影響を受けない）は同じでも、**理由が違っていた**。

→ 検査に **「その表を触る行が、本当にそのファイルにあるか」** を足したら、**その場で落ちた**。
★**鍵（どのクライアントか）だけでなく、表（何を触るか）も写さない。**
　どちらも**コードから読む**。

★関連＝使い捨てDBで測るときは **`service_role` に `bypassrls` を付ける**。
　付けないと「ポリシーが無いから0行」になり、**本番と違うものを測る**
（本番の service_role は RLS を素通りする）。

## 6. 片付けまでが④

- `pending/` の SQL を**適用済みへ移す**（★移したら、**それを参照している検査のパスも直す**。
  ★検査の先頭に**「SQL が実在するか」の節**を置くと、次に移したとき黙ってずれない）
- デスクトップの流し終えた SQL は **番号を外して「済み」に**（戻す SQL は番号なしのまま残す）
- **残った懸念を、次の宿題として番号付きで起票する**（「だいたい閉じた」で終わらせない）

## 7. ★「閉じた」の最終形は、**外から1表も届かない** ＋ **鍵を作る場所が0**

4段を終えたあと、まだ上がある。**仕上げの2つ**：

### ⑴ DB 側＝**全表が 42501**（「0行」で満足しない）

RLS だけで止めている表は **HTTP 200 で 0 行**が返る。
中身は漏れていないが、**GRANT が残っている＝ポリシーを1本うっかり足すと開く**。
→ **GRANT ごと外して、全表を 42501 にする。**

★**測るときは「読めない」だけでなく「書けない」も見る**
（INSERT / UPDATE / DELETE。★本番を汚さない形で＝
存在しない鍵を条件にした UPDATE/DELETE、INSERT は「絶対に残ってはいけない名前」で）。

★**段階ごとの数字を並べると、進んだことが伝わる**＝
「156行そのまま読めた → 200 だが0行 → **42501**」。

### ⑵ コード側＝**anon の鍵を作る場所を0にする**

寄せ終えたあと、**作り手の関数だけが残る**。そこで終わらせず**消す**。
消し切ると、**その種類の間違いは「書こうとしないと起きない」**ところまで行ける。

実例の順番（3回に分かれた）：

1. 使っていないコード（`benchmark.ts`）＝**呼び出し元0件・触る表が本番に無い**
2. その作り手（`supabase/server.ts`）＝**import していたのはさっきのファイルだけ**
3. **同じ形がもう1つ**（ブラウザ側の `client.ts`）＝呼び出し元0件
   → ★**依存パッケージ（`@supabase/ssr`）も使う場所が0になったので外せた**

★**2 と 3 は、1 を消したあとに初めて見える。**
「全部消した」と思っても、**もう一度数える**（`grep` の対象を「呼び方」から「**鍵の名前**」に広げる）。

### 見張りの形

- **`NEXT_PUBLIC_..._ANON_KEY` を渡している箇所**を数える（呼び方で数えない）
- **理由つきの一覧（allow-list）に無い作り手が1件でもあれば落とす**
- ★**一覧が空になったら、空のまま残す**（コメントで「足すときは理由を書く」と明記）
- **わざと1ファイル足して、名前つきで落ちることを確かめる**

★**依存を外したら lockfile も一緒に動く**（`package-lock.json`・`deno.lock`）。
**別の検査が走った副作用で動くこともある**ので、**差分の中身を見てから commit する**。
