# 同じ手順が3箇所に写してあるとき、違うのは1〜2点しかない

同じ「生成 → 形をそろえる → 検査 → 作り直し → 前の良い版に戻す」が**3箇所に写して**あった。
片方だけ古くなる事故が実際に起きていた（検査を1箇所にだけ足して、本番でだけ落ちた）。

**写しを1本にするとき、全部を一般化しようとしない。「本当に違う点」だけを数える。**
実例では**2点だけ**だった＝①**AI の呼び方**（SDK か fetch か）②**事実の食い違いの見方**
（どの章を何と突き合わせるか）。この2つを引数で受け取る形にしたら、残りは1本になった。

## やること

1. 3箇所を並べて置き、**行ごとに「同じ／違う」を付ける**。
2. 「違う」が集まっているところが**引数にすべきもの**。だいたい1〜2点しかない。
3. 1本にした関数は**判定を1つも外に出さない**（呼ぶ側は「呼び方」と「見方」だけ渡す）。
4. 1本にしたあと、**固定の入力で3経路の答えが一致すること**を機械で示す
   （★「動いた」ではなく「**同じ答えになった**」を示す）。

## 落ちていたものが見つかる

写しを1本に寄せると、**片方にだけ残っていた古い実装**が必ず出てくる。
実例＝同期経路の片方だけ **AI への説明文が日本語固定**で残っていた（非同期は前日に直していた）。
★**これは副産物ではなく、1本に寄せる目的のうちの1つ**（＝見つけるために寄せる）。

## 外へ持っていくときの形

Deno（Edge Function）は拡張子なしの相対 import も npm の裸の名前も解決できない。
**手で写す**代わりに、**機械で1枚にまとめ（esbuild）、ズレの検査を毎回通す**。
検査で見るのは3つ＝①置いてある束と作り直した束が sha256 で一致するか
②**束経由の判定が、もとの TypeScript 直叩きと1件も変わらないか**（★本命）
③外への依存（import 文）が1行も残っていないか。
