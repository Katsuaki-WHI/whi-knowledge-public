# グラデーション背景の上に、操作要素を直に置かない

**画面いっぱいに伸びるグラデーション背景**（上が濃色・下が淡色、のような）の上に、
ボタン・選択肢・小さな文字を**そのまま**置いてはいけない。
**ページの上のほうでは読めても、下のほうでは背景と同化する。**

## なぜ見落とすか

- 設計するときは**画面の上のほう**を見て色を決める。「背景が濃いから文字は白でよい」と判断する。
- ところが**中身が増えるとページは下に伸び**、同じ要素が淡色の側に来る。
- **開発中は短いデータで確認する**ので気づかない。**実機で実データを入れたときに初めて出る。**

実例：4問ぶんの選択肢を並べた入力画面で、白い丸ボタンと白いラベルが画面下部で完全に見えなくなった。
**描画ピクセルで測るとコントラスト比 1.00**（＝文字と背景がまったく同じ色）だった。

## 直し方

1. **操作要素のまとまりを、自分で地色を持つカードに載せる。**
   1問なら「設問文＋選択肢＋ラベル」をまとめて1枚のカードに。
   これで、そのカードが背景のどこに来ても色の関係が変わらない。
2. **要素の色は、そのカードの地色に対して決める。**
3. ★**影（text-shadow / box-shadow）で解決しようとしない。影はコントラストを作らない。**
   輪郭線と地色で差をつける。影は「読めない文字を少しマシに見せる」だけで、
   背景が明るくなれば同じように消える。
4. ★**カードの地色を、端末のダークモードで反転させない**（`dark:` を付けない）。
   地色だけ反転すると、その上の文字色との関係が崩れる。
   **背景を固定したなら、その上の文字色も固定する。** 片方だけ動かさない。

## 測り方＝計算値ではなく「描画ピクセル」で

CSS の色から計算したコントラスト比は、**背景がグラデーションだと当てにならない**
（`background-color` は透明で、実際に見えている色は親のグラデーション）。

**スクリーンショットを撮り、要素の矩形の中の画素から測る。**

```
その矩形の中で
  背景  = いちばん多く出てくる色
  文字  = 背景から輝度がいちばん離れた色（グリフの芯）
→ この2色でコントラスト比を出す
```

**すべての幅・すべての言語・ライト/ダークで測る。**
ページが長い画面では、**同じ部品でも位置によって背景が違う**ので、
「1箇所で測ってOK」にしない。

## ついでに見ておくこと

- **画面の端に固定表示（fixed）しているボタン**は、**下のコンテンツに重なる**。
  上にタイトル行がある画面では気づかず、無い画面だけで重なる。
  **要素の矩形が交差しないことを、狭い幅（320/375/390px）で実測する。**
- 小さな補助テキスト（「あと N 問」など）は**画面の下のほうに置かれがち**で、
  まさに背景が淡くなる位置に来る。**本体だけ直して補助テキストを忘れない。**

## チェックリスト

1. 操作要素は、自分で地色を持つ入れ物の上にあるか。背景に直置きしていないか。
2. コントラスト比を**描画ピクセル**で測ったか。計算値で済ませていないか。
3. 全幅 × 全言語 × ライト/ダークで測ったか。**1箇所だけで判断していないか。**
4. 影で誤魔化していないか。
5. 固定表示のボタンと、各画面の上端の要素が重なっていないか。
6. 本体だけでなく、**小さな補助テキスト**も同じ地色の上に載せたか。
