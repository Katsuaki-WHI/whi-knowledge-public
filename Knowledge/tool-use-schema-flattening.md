# Tool Use スキーマ設計の学び：top-level にオブジェクトを置かない

★**2026-09-18 更新。** 初版の結論は「**1項目だけ**のオブジェクトを作らない」だったが、
**複数項目のオブジェクトでも同じ壊れ方をした**ため、ルールを一段広げた（下記「その後わかったこと」）。

## 事象（2026-08-14・初版）
- AIレポートを Tool Use（構造化出力）で生成する際、初回の実生成が `invalid tool_use json` で失敗した。
- 原因＝モデルが**単一 body しか持たないセクション**を、`{"body": …}` という **JSON文字列＋末尾に余分な `}`** という壊れたJSONで**二重エンコード**して返した。
- 同じスキーマ内でも、**プレーン文字列**のフィールド（opening/closing のような単一の文字列）では起きなかった。

## その後わかったこと（2026-09-18）
- **2項目のオブジェクト**（`{lead, body}`）が、**閉じ引用符の欠けた JSON 文字列**で返ってきた。

```
"strengths": "{\"lead\": \"…\", \"body\": \"…なっています。}"
                                                        ↑ 閉じ引用符が無い
```

- 救済パース（`JSON.parse`）は壊れた JSON で失敗 → 文字列のまま残る → 検証で invalid →
  **レポート1本がまるごと表示不能**。同じ条件の4本中1本で発生（**非決定的**）。
- ＝「1項目だから起きる」のではなく「**オブジェクトだから起きる**」。

## ★教訓（現在のルール）
★**Tool Use スキーマの top-level は「文字列」「文字列の配列」「オブジェクトの配列」だけにする。
オブジェクト型の top-level プロパティを作らない。**

- `{lead, body}` → `xxxLead` / `xxxBody` の**2つの文字列**に割る。
- `{items: [...]}` のような**配列を1個だけ包むオブジェクト**は、配列そのものにする。
- **オブジェクトの配列（`items[]{title, body, …}`）は残してよい**。
  実測でも配列は文字列化されにくく、壊れても配列全体の `JSON.parse` は成功しやすい。
- ★これは「JSON文字列にしないでください」という**言葉の指示では直らない**。
  現に旧プロンプトには「オブジェクトやJSON文字列にしない」と明記してあったのに壊れた。
  **守らせたいことは、言葉ではなく構造で決める。**

## 既存データを壊さずにスキーマを変える型
スキーマを変えると保存される形も変わる。**表示側を全部直す**か**窓口で吸収する**かの二択で、
**窓口で吸収するほうが安全**だった。

- `normalize()` を「**内部の形（入れ子）に寄せる唯一の窓口**」にする。
  - 新（フラット）が来たら **入れ子に組み立てる**（使ったフラットキーは消す）。
  - 旧（入れ子＝既存キャッシュ）は**そのまま通す**。
- こうすると **型・検証・表示コンポーネントは一切変えなくてよい**（差分が窓口1ファイルに閉じる）。
- 保存は normalize の後なので、**新規生成も同じ形で保存される**＝キャッシュの形が分裂しない。
- ★別ランタイム（例：Deno の関数）に**同じロジックを複製している場合は同時に更新する**。
  片方だけ直すと、**本番の既定経路でだけ壊れる**。

## 検証のしかた（AI生成なしで固定ケース＋機械チェック）
1. スキーマを走査して **top-level に `type:"object"` が無い**ことを確かめる（ルールそのものを機械で守る）。
2. **実際に起きた壊れ方の文字列**（閉じ引用符の欠落）を入れて、
   **例外を投げず invalid に倒れる**ことを確かめる＝表示は落ちない・保存もされない。
3. **旧形式のケースを入れて、出力が入力とバイト一致**することを確かめる＝既存データが不変。
4. プロンプトのフィールド名がスキーマのキーと**一致している**ことを確かめる
   （名前を変えたのにプロンプトが旧名のままだと、AI がどのフィールドを埋めるか分からなくなる）。

★**「救済パースを足す」で終わらせない。** 救済は入口を広げる対症療法で、
壊れ方が1つ増えるたびに弱くなる。**本命は、そもそも壊れる形をスキーマから消すこと。**
