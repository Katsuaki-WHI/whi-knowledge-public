# 試作の「通らなければ出さない」を、お金を受け取ったあとにそのまま使わない

AI が書いたものを保存する前に機械で検査し、**外れていたら作り直す／通らなければ保存しない**——
試作では、これが正しいやり方です。悪いものを世に出さずに済みます。

**でも、お金を受け取ったあとは違います。**

> **お金を受け取ったのに、何も届かない。** これは、悪いものが届くより悪い。

同じゲートを2つの場面で使い分けます。

| | いつ | 何を守るか | 通らなかったら |
|---|---|---|---|
| **試作** | 作っている最中 | **悪いものを出さない** | **保存しない**（人が見る） |
| **購入後** | お金を受け取ったあと | **必ず届ける** | **人が引き取る**（止めない） |
| **購入前** | お金を受け取る前 | **売らない** | **自動で販売を止める** |

## 決めること4つ

### ① 作り直しの回数は、場面で変える

試作は1回で十分です（外れ方を人が見たいので）。**購入後は上限を増やします**（例：5回）。
★**間隔をあけること。** 同じ瞬間に叩き続けても結果は変わらず、費用だけ増えます。
★**回数はコードが持ちます。プロンプトには書きません**（言葉で縛らない）。

### ② 検査項目を「重い／軽い」に分ける

分ける基準は「**受け取った人に出したとき、事実が違うか／害があるか**」です。

- **重い**＝事実が違う／外に出してはいけない言葉／本人の言葉の誤引用／呼び方が違う
  → 通らなければ**自動では出さない**
- **軽い**＝長さ・文体・体裁
  → 通らなければ**そのまま出す**（読めないものにはなりません）

★この分類を先に決めないと、**軽い違反で配信を止める**（届かない）か、
**重い違反をそのまま出す**（事実が違うものを届ける）かの、どちらかに倒れます。

### ③ 重い違反が残ったときは、人が引き取る

1. 受け取った人には「**準備に時間をいただいています。できあがり次第お知らせします**」
   ★「エラー」「失敗」とは書きません。**受け取った人に落ち度はありません**
2. 運営に**即通知**し、**中身は必ず残す**（黙って捨てない＝直せない）
3. 人が直して**手動で届ける**
4. **最後の手段が返金**。★**自動返金にしない**（直して届けるほうが良いから）

### ④ 止めるのは「受け取る前」だけ

失敗率・1件あたりの呼び出し回数・費用の上限——どれかを超えたら、
**買う画面を自動で止めます**（「準備中」に切り替える）。
★**再開は人が手で行う**（原因を見ていないのに自動で戻さない）。
★★**判定は必ず購入前の導線に置く。払ったあとに止めない。**
画面で押せなくするだけでなく、**決済の入口でも同じ判定を通す**（多層）。

## 原価の見積もりも変わる

**作り直しが前提なら、1件あたりの API 呼び出しは1回ではありません。**
実測で「**1件＝平均2回**」（毎回1回目は通らず、作り直しで通る）でした。
**1回ぶんで計算すると、原価が半分に見えます。**
上限が5回なら**最悪5回**。平均と最悪の幅を、販売停止の閾値にも使います。
