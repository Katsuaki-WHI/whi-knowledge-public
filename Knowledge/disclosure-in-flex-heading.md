# 折りたたみ部品を「横1行の見出し」に置くと、本文が横に入り込んで見出しが潰れる

## 症状

見出しの横に「？」ボタンを置き、押すと説明文が開く部品（disclosure）を作ったとき、
**説明文が「？」の右に入り込み、見出しのほうが縦に潰れる**。

実例（なかまサーベイ・チーム運営ページ 2026-09-10 実測）：
375px で見出し「メールアドレスの入力」が **4行に折り返し**、その右の狭い帯に説明文が流れていた。
見出しは1行で読めるべきものなので、開いた瞬間にいちばん読みにくくなる。

## なぜ起きるか

部品が「ボタン」と「本文」を**兄弟として返す**（React ならフラグメント）作りだと、
呼び出し側の見出しが `display:flex` の1行だったとき、**本文もその行の flex アイテムになる**。

```
[見出しテキスト] [？] [本文……]   ← 全部が同じ行に並ぶ
```

`flex` の既定は `flex-wrap: nowrap` なので次の行へ逃げられず、
各アイテムが縮んで、テキストの多い見出しが縦に折り返す。

**同じ部品でも、呼び出し側が flex でない場所では正しく下に出る**ため、
片方の画面だけ壊れて見え、原因が部品側にあると気づきにくい。

## 直し方（2つセットで効く）

1. **本文に `flex-basis: 100%`（＋`width: 100%`）** を与える  
   → その行に収まらないので次の行へ落ちる。
2. **呼び出し側の見出しに `flex-wrap: wrap`** を足す  
   → `flex-basis: 100%` は **wrap が有効なときだけ**改行を起こす。片方だけでは直らない。

flex でない呼び出し元では `flex-basis` は無視されるので、**そちらの見た目は変わらない**
（＝既に正しく動いている場所を壊さずに直せる）。

## あわせて気をつけること

- **本文の文字の太さ・大きさを明示する。** 見出しが太字だと、本文がそれを**継承して太字になる**。
  本文は本文として読める重さに戻す。
- **`<p>` の中に `<p>` を入れない。** 見出しを `<p>` で書いていると入れ子になり HTML として不正。
  クライアント側で後から差し込む間は動くが、サーバー側で最初から開いた状態を描くと
  ブラウザのパーサが勝手に閉じて**ハイドレーションのずれ**になる。見出しは `<div>` にするのが安全。
- **開閉は `aria-expanded` と `aria-controls` で伝える。** 読み上げ用の名前は辞書から渡し、
  キーボード（Enter・Space）でも開閉できることを**実際に押して**確かめる。

## 検証の勘どころ

**「押したら開く」だけを確認して終わりにしない。**
開いた本文の矩形が**ボタンの下端より下にあるか**（`getBoundingClientRect().top >= button.bottom`）を
実測する。見た目の判定を目視だけに頼ると、狭い幅の破綻を見落とす。
同じ部品を使っている**全ての呼び出し元**で確認する（1箇所直して他が同じ形とは限らない）。

## 一般化

**折りたたみ部品は「本文がどこに出るか」を部品側で保証する。**
呼び出し側のレイアウト（flex かどうか）に結果が左右される作りは、
使う場所が増えるほど壊れる場所が増える。
部品は「ボタンは見出しの横・本文は必ずその下」を自分で守るように書く。
