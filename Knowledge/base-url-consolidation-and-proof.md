# ベースURLの集約と、「値が変わっていない」ことの証明のしかた

ドメイン移行に備えて「URLの先頭部分（ベースURL）」を1箇所にまとめるときの型。
**値を変える作業ではない。「どこから取るか」だけを変える作業**なので、
**集約前後で出力が1文字も変わらないことを証明できて初めて完了**になる。

## 1. まず散らばり方を数える

同じ意味の値が、たいてい何通りかの書き方で散っている。実例（なかまサーベイ・src/ 13箇所）：

| 書き方 | 危険度 |
|---|---|
| ドメインを直書き | ★高＝環境変数で切り替えられない。ドメイン移行で必ず編集が要る |
| `process.env.X \|\| ドメイン直書き` | 中＝環境変数名が複数あると、片方が未設定で常にフォールバックになる |
| `window.location.origin \|\| ドメイン直書き` | 中＝フォールバックだけが移行の負担 |
| **`window.location.origin` のみ** | **低＝寄せなくてよい**（いま開いているホストに自動追従するため） |
| 別プロダクトのドメインをフォールバック | ★高＝フォーク時の残骸。気づかず別サイトのURLを配る |

★**線引き＝「ドメインを直書きしている」「環境変数を自分で読んでいる」箇所だけ寄せる。**
`window.location.origin` だけを見ている箇所は**移行で直す必要がない**ので、無理に寄せない
（寄せるとSSR時の値が変わる副作用が出るだけ）。

## 2. 関数は2つに分ける（1つにすると事故る）

- **`serverBaseUrl()`** ＝環境変数 → 無ければ本番URL。**`window` を見ない。**
- **`getBaseUrl()`** ＝ブラウザなら `window.location.origin`、それ以外は `serverBaseUrl()`。

★**初回描画の初期値（`useState` の初期値など）には必ず `serverBaseUrl()` を使う。**
`getBaseUrl()` を使うと、サーバーの描画は本番URL・クライアントの初回描画は現在のオリジンになり、
**ハイドレーションのズレ**になる。「マウント後に `window.location.origin` へ更新する」形は維持する。

## 3. 寄せない例外は、理由をコードに書く

決済の戻り先URL（Stripe の `success_url` 等）は **`環境変数 || いま来ているリクエストのホスト`** が正しい。
本番URL固定にすると、プレビュー環境やドメイン切り替え期間中に**別のホストへ飛ばしてしまう**。
「ここだけ別なのはなぜか」を集約ファイルのコメントに書いておかないと、次の人が善意で壊す。

## 4. ★証明のしかた（git stash で前後を比べる）

1. 環境変数を**外した状態**にする（＝本番でフォールバックに落ちる条件を再現）。
2. **集約後**の出力を採る（ベースURLを決めている全箇所の評価値／メール本文に入るURL／実画面が出すURL）。
3. `git stash` で**集約前**に戻し、同じ手順で採る。
4. `diff` して**1文字も違わない**ことを確認。`git stash pop` で戻す。

★メールは**実送信しない**。本文ビルダーが使っている定数の決め方を実ファイルから読み取り、
`${BASE_URL}` を実値に置き換えた文字列を並べて比べればよい。

★**環境変数を設定した状態でも1回見る**。集約後は全経路が同じ値で揃うが、集約前は
経路ごとにバラバラ（直書きは本番URL・env参照はlocalhost）になる。**その食い違いこそが直したかったもの**。

## 5. Vercel の環境変数は「型」で値が読めるかが変わる

- **Secret 型は `vercel env pull` でも値が返らない**（空文字で降ってくる）。`vercel env ls` は名前と日付だけ。
  → **あとから照合できない。**
- **Config 型なら `vercel env pull` で値が読める。**
- ★**URL のような秘密でない設定値は Config 型にしておく。** Secret 型にすると、
  「本番の値が何か」を確かめられないまま集約するはめになる。
- ★どうしても読めないときの回り道＝`NEXT_PUBLIC_*` は**クライアントの JS に焼き込まれる**ので、
  デプロイ後に配信されているチャンクを grep すれば**ビルド時に解決された値**が分かる
  （ただし分かるのはビルド時の値であって、サーバーが実行時に読む値ではない）。

## 6. 本番反映後に見ること

- `git merge-base --is-ancestor <sha> origin/<本番ブランチ>` が成功する。
- **`vercel inspect --logs <正式URL>` の `Commit:` 行**が push した sha と一致する
  （`vercel ls` の一覧には sha が出ない）。
- 配信されている JS に**意図した値だけ**があり、**別プロダクトのドメインが混じっていない**。
