# Resendの予約送信は「30日先まで」が上限（超過時の挙動は未文書化）

メール送信サービス Resend の予約送信（`scheduledAt` / scheduled emails）の制約を一次情報で確認した（2026-08-15）。

## 確認した事実（一次情報）
- **上限＝30日先まで**。Resend公式ドキュメント `resend.com/docs/dashboard/emails/schedule-email` に「Emails can be scheduled up to 30 days in advance.」と明記。
- **上限を超える予約を投げたときの挙動は公式ドキュメントに記載なし（未文書化）**。schedule-email ページにも API reference（`emails/send-email`）にも、超過時のエラーコード・拒否挙動の記述がない。
- → 実装では「30日超の予約はAPIエラーが返る前提」で**防御的に扱い**、実挙動が必要なら**実験で確認**する（推測で成功前提にしない）。

## 設計への影響
- 「開始時に全通を一括で予約しておく」方式は、**すべての配信が30日以内に収まる場合にのみ成立**する（例：3週間・週次の3通は全部30日以内）。
- **数ヶ月先や半年〜1年先の配信**（長期の定期配信・再通知リマインド等）は30日を超えるため**一括予約できない**。定期実行（cron / 日次ジョブ）で「その日に送るべきものを走査して送る」方式が必要になる。

## 教訓
- 予約送信サービスに「一括予約で全部済ませる」設計を載せるときは、**予約可能期間の上限を一次情報で先に確認**する。上限を超える予定は予約でなく定期実行（cron）で拾う。
