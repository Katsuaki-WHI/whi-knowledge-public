# 長い作業は「1回の返答を短く・1手ずつ止まる」

★**長い作業（分割・棚卸し・一括の置き換え）は、1回の返答で全部やろうとすると途中で切れる。**
切れると**どこまで済んだか分からない状態**が残り、やり直すと**同じ塊を二度移す**危険がある。

## やること

1. ★**手順を①②③④に割り、各手の最後で必ず止まる**（報告は数字だけでよい）。
2. ★**切れたら、まず `scratchpad` と `git status` で「どこまで済んだか」を確かめる**（推測で続けない）。
   ★**途中の成果物は scratchpad にファイルで残す**＝会話が切れても残る。
3. ★★**画面下の「`/clear` to save N tokens」を先に見る。**
   同じ段で2回以上切れたら、**通信のせいにして再試行させる前に `/clear`**。
4. ★**不可逆な手（移動・置き換え・削除）は、その手だけで1回の返答にする。**
5. ★**二度やっても安全な形にしておく**（＝冪等）。移す塊は**先に定義ファイルに固定**し、
   「元 −（移した塊）＋（案内）＝分割後」のような**機械で判定できる等式**を持つ。

## 実例（なかま 2026-10-12）

CLAUDE.md の4回目の分割で、**同じ段で返答が4回切れた**（`response stopped arriving`）。
★**原因は文脈の大きさ**（**479k → 524k tokens**）で、通信ではなかった。
★**再試行を重ねたぶんだけ文脈が増え、さらに切れやすくなっていた**（＝悪循環）。
→ 翌日（5回目の分割）は**①〜④に割って1手ずつ止まる**形にしたところ、**1回も切れずに通った**。

## 気をつけること

- ★**「あと少しだから一気に」が、いちばん切れる。** 残りが少ないときほど1手に割る。
- ★**切れた直後に同じ内容を投げ直さない**（文脈はもう増えている）。
- ★**止まることを前提に報告を短くする**＝長い表・全文の引用を途中の報告に入れない。
