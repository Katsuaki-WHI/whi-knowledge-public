# AIが書いたHTMLをページに挿し込むときは、`<style>` と body/html 向けの指定を必ず取り除く

AIに「HTMLで出力して」と頼むと、**完全なHTMLドキュメント**（`<!DOCTYPE>` `<html>` `<head>` `<style>` `<body>`）が返ってくる。
それをそのままページの一部に挿し込むと、**`<head>` の `<style>` がページ全体に効く**。

## なぜ気づきにくいか

- `<style>` は**スコープを持たない**。どこに挿し込んでも、ページ全体が対象になる。
  挿し込む側の `<div>` にクラスを付けても囲い込めない。
- 壊れるのは**そのコンテンツを表示した画面だけ**。他の画面は正常なので「そのページだけおかしい」に見える。
- **エラーは出ない。** 崩れているだけなので、ログにも例外にも残らない。
- ★**同じ機能でもデータによって出たり出なかったりする。** 新しい形式で保存されたものは崩れず、
  古い形式が残っているものだけ崩れる＝**テスト用データでは再現しない**。

実際の壊れ方（実測）：
```css
* { margin: 0; padding: 0; }                    → ページ中の余白が全部消えて要素が密着
body { background: #F8FAFC; }                   → ページの外側が灰色になる
body { padding: 20px; max-width: 800px; margin: 0 auto; } → 中央に白いカードができる
```
ボタンまで痩せる（64px → 44px）。**触っていないはずの場所が、全部ずれる。**

## やること

挿し込む**直前**に、文書レベルのものを落とす：

- `<style>…</style>` を全部
- `<head>…</head>` を全部（title・meta・link をまとめて）
- `<link>`（外部CSSの読み込み）
- `<!DOCTYPE …>`
- `<html>` `<body>` は**タグだけ剥がして中身は残す**

★**本文の見た目は壊さない。** 要素に直接ついた `style="…"` やクラス指定はそのまま残す
（消すのは「ページ全体を対象にした指定」だけ）。

## 設計として大事なこと

1. **取り除く処理は1つの関数にまとめ、挿し込む全箇所から呼ぶ。**
   同じ挿し込みが他の画面にもあることが多い（今回は依頼された2箇所の他に4箇所あった）。
   **片方だけ直すのは、次に壊れる場所を残すだけ。** grep で未対策が残っていないことを確かめる。
2. **保存済みのデータは書き換えない。** 表示の直前で整えれば、古いものも読めたまま残る。
   データを作り直すと**中身が変わる**（AI生成物は生成のたびに別物になる）。
3. **そもそもHTMLで受け取らない。** 構造化された形式（項目ごとの値）で受け取り、
   見た目はこちら側の部品で描くほうが安全。今回も新形式はこの問題が起きない。

## 確かめ方

- 関数の固定ケース：**取り除けているか**と同じくらい**本文が残っているか**を確かめる
  （取り除きすぎは、レポートが読めなくなるという別の事故になる）。冪等・null・空文字も。
- 実画面：**崩れる前と後で、ページ側の値が元に戻るか**を測る
  （body の背景・余白・最大幅、関係ないボタンの幅、要素どうしの余白）。
  ★**「そのコンテンツが正しく見えるか」だけ見ても足りない。関係ないはずの場所を測る。**
