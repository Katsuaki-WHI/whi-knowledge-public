# 同じ欄に2つの役割を持たせない。言葉で縛る前に、欄を分ける

## 事象

AI に「2文で書く」よう指示した欄で、**2文目だけが毎回崩れた。**
1文目は「相手にどう見えていたか」、2文目は「自分ではどう見ていたか」。
2文目は**完成した1文をこちらで作って渡し、そのまま写すだけ**でよかったのに、
**5回書き換えても守られたのは5件中2件**だった。

試したことは全部：

| 試したこと | 結果 |
|---|---|
| 型を明記（「1文字も形を変えてはならない」） | × |
| 材料に完成した1文を入れて「そのまま写せ」 | × |
| その1文を囲みで目立たせる | × |
| 「書き終えたら入っているか確かめよ」の自己チェック | × |
| その1文を**プロンプトのいちばん最後**に置く | 2/5 まで改善 |
| 「1文目と違うものになることがある。それでよい」と**理由**を書き添える | 変わらず |
| **書いてはならない語を名指しで挙げる** | ❌**悪化**（名指しした語を呼び込んだ） |

## 原因

**1つの欄の中に、性質の違う2つの文を入れさせていたこと。**

モデルは1つの欄を「ひとまとまりの文章」として扱い、**流れを整えようとする**。
2文目が1文目と別のことを言っていると、それを「揃えるべきずれ」と受け取り、
1文目に寄せて書き換えてしまう。**人間の書き手なら同じことをする**ので、
これはモデルの不具合ではなく、**指示の設計の問題**である。

## 対処

**欄を分けた。** 出力スキーマに1文専用の欄を足し、
- 元の欄には1文目だけ
- 新しい欄には「渡した1文を写すだけ」

**その回で5/5 通った。** 言い方は一切強めていない。

## 教訓

- **同じ欄に2つの役割を持たせると、言葉でいくら縛っても混ざる。**
- **言い方を強める前に、「欄を分けられないか」を先に考える。**
  プロンプトを厚くするのは、構造で解けないと分かってからでよい。
- **禁止語を名指しで列挙すると、かえってその語を呼び込むことがある。**
  「正しい形」を示すほうが安全で、「間違いの形」を並べるのは最後の手段。
- 既存の出力を壊さずに欄を足すには、**新しい欄を「あるときだけ描く」形にする**
  （古いデータには無いので、古い表示は変わらない）。

## 付随して分かったこと

**開発サーバー（`next dev`）が、API ルートの出力スキーマの変更をホットリロードで拾わないことがある。**
欄を足した直後の5件はすべて空欄で返り、**開発サーバーを再起動したら一発で入った**。
**スキーマを変えたら、開発サーバーを再起動してから確かめる。**

## 関連

- 版の判別は「構造」で行い、版番号に頼らない＝[[one-reader-before-adding-a-format]]
- 実際に生成して中身を読むまで品質は判断できない＝[[build-pass-not-runtime-ok]]

## 再発（2026-09-14・なかま 王様の鏡 v2）——「残りは全部ここに」と書くと、隣の欄が空になる

差が無い回の第四章に「使い道（誰と・どの場面で使うか）」を書かせようとして、
読み解きの欄に「**重なっていると述べたあと、残りはすべて使い道に充てる**」と書いた。
処方箋の欄にも「使い道を示して締める」と書いた。＝**同じ役割を2つの欄に置いた。**

結果、**英語版が処方箋を空文字にして、全部を読み解きの欄に入れた**（2回とも）。
「空にするな」と書き足しても直らなかった。

★**モデルは「残り全部」を素直に受け取る。** 隣の欄に同じ役割が書いてあれば、
どちらか一方に寄せるのが文章として自然だからそうする。**不具合ではなく、指示の設計の問題。**

直し方は言い方ではなく**役割の分割**：
- 読み解きの欄 ＝ 重なっていることだけ（1〜2文）。「使い道はここに書かない」と明示
- 処方箋の欄 ＝ 使い道だけ（1〜2文）

→ 日英とも両方が埋まった。

**チェックリスト**
- 1つの欄の指示に「残りはすべて」「あとは自由に」と書いたら、**隣の欄と役割が重なっていないか**を見る
- 「空にするな」と書き足す前に、**その欄にしか無い役割があるか**を確かめる
- 欄が空になる不具合は、**片方の言語でだけ出ることがある**（日本語は埋まり、英語だけ空だった）
  ＝生成物は必ず**日英とも中身を読む**
