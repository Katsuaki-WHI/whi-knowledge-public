# `as` のキャストは型の検査を黙らせる（綴り違いが「いつも null」になる）

> 【Public可・★DB・Server Action の戻り値から欄を1つ取り出すときに読む】

## いつ読むか

- DB・Server Action・RPC の**戻り値から欄を1つ取り出す**コードを書くとき。
- `as { … }` を書きそうになったとき。
- 「`?? null` を付けておけば安全」と思ったとき（★**安全ではなく、静かに間違う**）。

## 何が起きるか

```ts
// ✗ その場でキャストすると、欄の名前が違っても tsc は何も言わない
const teamId = (team as { id?: string } | null)?.id ?? null;   // 実際の欄は teamId
```

戻り値には `id` という欄が無いので **`teamId` はいつも `null`**。
その先の判定は**いつも false** になる。

★★**キャストが tsc を黙らせている**ので、**型でも検査でも気づけない。**

## なぜ長く残るか — 症状が「何も無い」

`null` → false → **今までどおりの画面**。
**エラーも出ず、ログも出ず、検査も通り、画面も壊れない。**
壊れたのは「新しい分岐がいつも通らない」ことだけなので、
**その分岐を実際に通す人が現れるまで、誰も気づかない。**

## どうするか

1. ★★**戻り値の型が推論できる関数には `as` を書かない。**
   ```ts
   const teamId = team?.teamId ?? null;   // 綴り違いはその場で tsc が止める
   ```
2. `as` を書いてよいのは**型が本当に分からないとき**だけ（外部APIの生JSON・`JSON.parse` の結果など）。
   そのときも**欄の名前を1つずつ実体で確かめてから**書く。
3. ★**1つ見つけたら、同じ行・同じ形を全部数える**（AI-RULES §13-1 ⑴）。
   実例＝同じ行の既存コードが**6日前から同じ間違い**をしていた
   （版が1つしか無かったので表に出ず、**2つ目の版を公開した瞬間に全件の母数が黙って飛ぶ**ところだった）。
4. ★**検査には「通る側の実例」を1つ入れる**（AI-RULES §13-1 ⑴）。
   「そう書いてあること」は、**効くことの証明にならない**。

## 見つけ方

```bash
# ★ その場キャストを数える（理由のあるものだけ残す）
grep -rnE '\(.+ as \{[^}]*\}( \| null)?\)\?\.' src/
```

★**0件にするのが目的ではなく、増えたら気づくのが目的。**
