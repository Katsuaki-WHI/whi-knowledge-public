# データ修復の影響範囲は「直す行」ではなく「その値を読んでいる全ての計算」で数える

本番データを直すとき、影響範囲を**直す行の数**で見積もってしまいがちだ。
しかし実際に動くのは、**その値を入力にしている計算のすべて**である。

## 見落としやすい2つ

### ① 個人の値を合算して出している「集団の指標」

1人の値を直すと、**その人が属する集団の指標が動く**。
集団の指標は、その集団の全員から計算されるので、**直していない人のページの表示も変わる**。

実例：ある人の配分を直したところ、**9つの集団のうち3つで集団分類が変わった**。
直した人は各集団に1〜3人だけなのに、**その集団の全員の画面が変わった**。

### ② 「固めてあるもの」と「毎回計算しているもの」が混在している

表示を固定する仕組み（結晶化・スナップショット）を**一部にだけ**入れていると、
同じページの中で**動かない部分と動く部分が混ざる**。

実例：個人向けの比較表示は固めてあったので動かなかったが、
同じページの集団分類は固めていなかったので動いた。
**「固めたから安全」と考えると、固めていない部分を見落とす。**

## 見積もりのしかた

修復の dry-run では、行数だけでなく**読み手ごとに**数える。

```
1. その列を読んでいる計算を全部挙げる（画面・集計・生成・メール・書き出し）
2. それぞれについて
   - 固めてある（保存済みの値を出す）      → 動かない
   - 毎回計算している                      → 動く
3. 「動く」ものについて、影響する人数を数える
   ★直す行の人数ではなく、その計算を見る人数
4. 変わる前と変わった後を、実際に計算して並べる（型・分類・順位など）
```

★**3 と 4 を dry-run の出力に入れておく**と、承認する人が「何が変わるか」を見てから決められる。

## 直すか、戻すかの判断材料

- **直した値のほうが事実に近いか。** 仮の値だったなら「変わった」ではなく「**正しくなった**」。
- **すでにその表示を見た人がいるか。** 見ていれば、変化に気づく人がいる。
- **お金が動いているか**（購入・請求に紐づくか）。
- **外部の相手が見るものか、内部だけか。**

これらを並べたうえで、**決めるのは依頼した人**。実行した側は材料を出すところまで。

## チェックリスト

1. 直す列を**読んでいる計算**を全部挙げたか。行数だけで見積もっていないか。
2. そのうち**固めてあるもの／毎回計算しているもの**を分けたか。
3. 毎回計算しているものについて、**変わる前と後を実際に計算して並べた**か。
4. 影響を**直す人数でなく、表示を見る人数**で数えたか。
5. 適用前に**対象行の全列を控え**、ハッシュを残したか（戻せるか）。
