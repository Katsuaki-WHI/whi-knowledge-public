# ★AI の呼び出しの守り＝正典（SQW・なかま 共通）

2026-10-11〜12 確定。★**SQW と なかま の両方に効く。数字だけが製品ごとに違う。**

---

## 0. いちばん上の決め

★★**サーバーレスの寿命は「公式」ではなく「実測」で決める。**

★**実測＝約200秒**（2026-10-11・なかまの Edge が起動 12:13:25 → shutdown 12:16:45＝**約200秒で外から切られた**。
10-02 の 199秒とも一致）。
★**公式の「Paid 400秒」は実測で裏づけられていない**＝★**当てにしない**。

★**定数の名前で出どころが分かるようにする**
（SQW は `EDGE_HARD_LIMIT_MS` → **`EDGE_OBSERVED_LIFETIME_MS`** に変えた）。

---

## 1. 守りは3つセット（どれが欠けても袋小路になる）

| | 何を |
|---|---|
| ① | **1回ごとの呼び出しに時間の上限**（外部APIはいつまでも待つ） |
| ② | **やり直しの前に残り時間を見て、足りなければ呼ばない**（打ち切られない範囲でしか始めない） |
| ③ | **見張り**が、一定時間を過ぎた `running`／`pending` を `failed` に倒す（理由を残す・`completed` には触らない） |

★**なぜ要るか**＝**打ち切られた実行では `catch` が走らない**ので、
ジョブが「作っている最中」のまま残り、**壊れている状態とまだ動いている状態が見分けられない**。

## 3. ★★余白はゼロにしない（2026-10-11 15:39 の事故）

★**本番で AI 生成が1本も作れなくなった**（v1 も v2 も）。

**原因**＝持ち時間を「1回の上限＋後処理」と**ぴったり同じ**にしたため、判定が

```
elapsed + 165,000 + 20,000 <= 185,000  →  elapsed <= 0
```

となり、★**起動に1ミリ秒かかった時点で必ず「呼ぶ時間が残っていない」**になった。
（入口から判定までにジョブの読み込みと材料の組み立てが入るので、`elapsed` が 0 になることは実行時に起きない。）

**直し**＝⑴**上限 165 → 160秒**（＝**起動の余白5秒**）⑵**判定を `<=` → `<`**（★余白ゼロの設定をそもそも通さない）。

★★**決め**＝**余白は「0 より大きい」で持つ。判定は `<`。**
★**実行時に 0 にならない値は、検査も 0 以外で試す**（実測の2倍など、現実に起きる値で）。
★**同じ値を試している検査項目が2つ無いか確かめる**（余白ゼロの設計では「始まった直後(0)」と「ちょうど」が同じ 0 になる）。

## 3-B ★★検査の「余白」は倍率でなく絶対値で持つ（2026-10-13 追記）

★★**決め**＝**`上限 − 実測の最長 ≥ 20秒`。20秒を切ったら、上限を上げるのではなく材料を小さくする。**

★**なぜ倍率をやめたか**＝**壁が動かない**。
上限の側には **`1回の上限 ＋ 後処理 ≤ 1実行の持ち時間 ≤ 実測の寿命（約200秒）`** という壁があるので、
**実測の最長が伸びるほど倍率の要求だけが伸びて、壁の内側に収まらなくなる**
＝★**コードは正しいのに検査だけが落ちる**。

★**実例（なかま・2026-10-12）**＝実測の最長が **136,257ms** になり、
**136.3 × 1.3 ＝ 177.1秒 > 上限165秒** で**倍率ルールだけが落ちた**。
★**上限は上げられない**（165 ＋ 25 ＝ **190** ≤ 実寿命 **200**）。
→ なかまは **`MIN_HEADROOM_MS = 20_000`（絶対値）**に直した（**2026-10-13 実装済み**）。

★**余白が20秒を切ったときに打てる手**＝⑴**材料を小さくする** ⑵**章を分けて呼ぶ回数を増やす**
⑶**モデルを速いものにする**。★**「上限を上げる」は選べない。**

★**あわせて**＝**実測の最長はコメントに書くだけでなく検査に固定する**（放っておくと事実と違っていく）／
★**わざと壊して落ちることを確かめる**。

### ★SQW 側のいまの状態（2026-10-13 実測・★直していない）

- ★**SQW の検査はまだ倍率で縛っている**＝「上限は実測の最長の **1.05倍**以上」。
- ★**絶対値で見ると、SQW はいま 20秒を切っている**
  ＝**上限 160,000 − 実測の最長 147,500 ＝ 12.5秒**。
  → ★**そろえると「材料を小さくする」側の宿題になる**ので、**この回では直していない**
  （直すと検査が落ちるだけで、製品は何も良くならない）。
- ★**SQW には絶対値の節も既にある**＝「実寿命 − 持ち時間 ≥ 10秒」（いま 15秒）。
  ★**見ている場所が違う**（実行の壁／1回の呼び出しの余裕）。
- ★**SQW が壊れにくい理由**＝**作り直しが別の実行**なので、1回打ち切られても失敗に倒れて次で作り直せる。
  ★**それでも「打ち切られた」は買った人には失敗なので、宿題として残す。**
- ★**実測の最長の値そのものが古い**（2026-08-13 の v1 の値）＝**そろえる回に取り直す。**

## 4. ★★「Edge を出したら、実生成1本まで確認に含める」

★**AI を呼ばない確認（401／403／400／404 を前後で叩く）だけでは足りない。**
2026-10-11 の事故では、**塞ぐ側も通す側も前後で6通りとも同じ**だったのに、
**AI 生成が1本も作れない状態**になっていた。
★**AI を呼ばない確認は「AI が呼べなくなったこと」を構造的に見つけられない。**

- **Claude Code は AI を呼ばない**（費用・承認）ので、**かつさんが1本押して確かめるところまでを手順に入れる**。
- **押す場所**＝`/{lang}/admin/sqw/v2-preview`（★2026-10-12 から。それ以前は `/{lang}/admin/preview`）。
- **確かめること**＝⑴画面にレポートが出る ⑵`ai_usage_log` が**1件増える** ⑶`ai_generation_jobs` が `completed`。
- **失敗したら**＝`ai_generation_jobs.error_message` を読む
  （★2026-10-12 から🧪の画面が**その理由をそのまま出す**）。
